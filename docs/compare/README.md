# 对照图库

两组成品图，都是**同一句指令、同一颗 seed、同一对输入图**，唯一差别是某个数值来源被换掉了。
留在这儿的目的：以后再有人问"改了 X 会不会换图"，先翻这两组找量级，别凭印象；
以及记住判读口径 —— **只报"百分之几十像素不同"会把人带跑**（我在 §22 上就这么栽过一次），
必须连分级（>4 / >16 / >32）、平均通道差、PSNR 一起报，再看构图有没有动。

| 目录 | 换掉的是什么 | 实测记录 | 结果 |
|---|---|---|---|
| `miopen-fast/` | MIOpen 选核策略（`MIOPEN_FIND_MODE=FAST` → VAE 换了一套卷积内核） | §22 / §22.1 | 54.1% 像素逐位不同；`>16` 占 **0.70%**；平均 1.12/255；PSNR **36.36 dB**。构图没动。看得出来的是**垂着那只手的袖口卷起程度**不同 |
| `llama-cond/` | 编码引擎（8B 在图里算 → 换成 llama.cpp 出的那 115 行 pre-norm，条件逐行余弦 0.98247） | §23、§24 | 54.0%~56.7% 像素逐位不同；`>16` 占 **0.330%（干净那对）** / 0.385%；平均 0.891/255；PSNR **38.40 / 38.19 dB**。构图量过没动（掩膜质心两腿一致）。看得出来的是**抬起那只手的袖口门襟多了一颗金属扣** |

`llama-cond/` 里有**两对**，别看错：`index-live.html`（`A-fork` vs `C-live`，同一对输入像素，§24）是**该信的那一对**；
`index.html`（`A-fork` vs `B-llama`，§23）那条离线腿的条件是从**原始记录文件**切的，而生产输入是
`prepare_upload` 之后的图，两边输入差着 ±1 级（平均 0.94~1.09/255）⇒ §23 的对照混进了第二个变量。
结论没变（两对的分级与 PSNR 几乎一样），但方法上的账要记：见 §24 与 `docs/comfyui-measurements.md` §0 那条"输入固定两张"。

**两组都不是逐位相同。** 所以它们同时是反面材料：一旦开了 `FAST`、或上了 llama.cpp 那一档，
"同 seed 出同一张图"这把手艺就没了 —— §9 和 §15 那两次验收都靠它。要不要用，看的是这两组的**画质**值不值那把手艺，
这是人判的，不是数判的。

## 怎么看

每个目录里都有 `index.html`：擦除滑杆（同一位置来回切）、闪对比（0.5 秒一跳）、1:1 原尺寸三档全有。

```bash
xdg-open docs/compare/miopen-fast/index.html
xdg-open docs/compare/llama-cond/index.html
```

不想开浏览器就先看这三张：`*-pair*.png`（缩略并排）→ `hotspot-pair.png`（差异最密那块放大 2 倍）→
`where-*changed.png`（通道差 >16 标红、底图压暗，黑处完全没变）。

## 图是怎么来的（重跑一次约 10~15 分钟 GPU）

原始脚本在 `/tmp`（重启就没），方法都在实测记录里，照着重写即可：

- `miopen-fast/`：`/tmp/mio/e2e2_run.sh` 的四种制度（P2 = 没开 FAST、P3 = 空 db + FAST），
  拆图脚本 `/tmp/mio/make_cmp.py`。判读见 §22。
- `llama-cond/`：`/tmp/llama-inj/run_t1.py`（注入腿用 `comfy_nodes/qwen21_precomp_cond.py`），
  条件由 `/tmp/llama-inj/make_pt.py` 从 §19 的 `pre.bin` 切出（三道断言防的就是 §18 那次"整块错 14 行"）。判读见 §23。
- 两组的墙钟、find-db 行数、掩膜统计都抄在对应小节里，不必重跑就能引用。
