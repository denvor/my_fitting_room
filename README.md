# 试衣间

传一张本人照片和一到两张参考图，生成"你穿着它"的图。本机网页，自己用。
三个分类：**一件衣服**、**上衣加裤子/裙子**（两张参考图）、**换个发型**（参考图是别人的头发）。
两条生成来源可选：token plan 的 `qwen-image-3.0-pro`，或本机 ComfyUI 的 `qwen-image-2.1 turbo`（不花额度）。
输出有 480p / 720p / 1K / 2K 四档，**默认 1K**（两档低的只有本机能用，见「输出尺寸」一节）。
参考图可以从本地上传，也可以从 `data/samples/` 那个图库里挑。

设计与实测记录：`docs/superpowers/specs/2026-10-26-qwen-tryon-design.md`（基线）、
`docs/superpowers/specs/2026-10-27-comfyui-source-design.md`（第二个来源）、
`docs/superpowers/specs/2026-11-01-modes-and-samples-design.md`（三个分类与 sample 图库）。

## 装与起

```bash
uv pip install --python .venv/bin/python -r requirements.txt   # 或任意 pip install -r requirements.txt
.venv/bin/python dev_run.py
```

- 本机打开 `http://127.0.0.1:8000`，局域网设备用本机 IP 加 `:8000`（服务绑 `0.0.0.0`，同网络内任何设备都能访问，所以放公网前先看下面「登录」一节）。
- 接口地址、密钥、模型名从 `.env` 读：`OPENAI_URL`、`API_KEY`、`MODEL`。图像生成地址由 `OPENAI_URL` 去掉结尾的 `/compatible-mode/v1` 再接 `/api/v1/services/aigc/multimodal-generation/generation` 推导出来。
- 可选项：`TRYON_SOURCE`（`api` 或 `comfyui`，**缺省 `comfyui`**）、`COMFY_URL`（缺省 `http://127.0.0.1:8188`）、
  `TRYON_PASSWORD`（登录口令，缺省为空 = 不设登录）、`TRYON_COOKIE_SECURE`（`1` = 登录 cookie 只走 HTTPS）、
  `TRYON_SIZE`（`480p` / `720p` / `1k` / `2k`，**缺省 `1k`**）。
  这几个只是默认值，设置页里存的值优先。
- `.env` 和 `data/` 都不进版本库。

## 登录

一个共享口令，不做账号体系。`/api/login` 校验口令，通过后发一枚 Flask 自签的 cookie（`mfr_auth`，`HttpOnly`、
`SameSite=Lax`、30 天），此后所有页面、接口、图片文件都要带上它 —— 拦截是 `tryon/auth.py` 的 `before_request`，
**在网关这一层，不在前端**：浏览器里的路由守卫挡不住 `curl -X POST .../api/tryon`，那正是会烧额度的那一条。
放行名单只有三项：登录页、登录接口、静态资源。

- 口令为空时网关整个不装，`python dev_run.py` 在局域网里照旧免登录（启动时会打一行提示）。
- **公网入口 `mfr_wsgi.py` 没口令直接拒绝启动**，而且拒绝的方式是一页能读的说明，不是一片白屏：
  在 `.env` 加 `TRYON_PASSWORD=<你的口令>` 再 reload。静默无保护地跑着比启动失败难查得多。
- 签名密钥存在 `data/secret.key`（首次启动自动生成，权限 `600`），所以重启服务不会把人踢回登录页；
  删掉这个文件等于所有人的登录作废。
- 连错 5 次会按来源 IP 冷 15 分钟（`429`，这段时间连对的口令也不放行）。这条在 nginx 后面**仍然按真实
  客户端算**：nginx 的 `uwsgi_pass` 会把客户端地址放进 uWSGI 包里，实测日志里记的是 `192.168.199.171`
  这样的局域网地址，不是 `127.0.0.1`（先前这里写的"退化成全局限速"是没实测的担心，2026-10-30 证伪）。
  再多跳一层代理（比如云端 CDN）就要重新确认这件事。
- 登录接口只收 JSON，跨站表单发不出 `application/json`，所以顺带挡了 CSRF。口令比对走 `hmac.compare_digest`。
- 走公网请站在 HTTPS 后面并设 `TRYON_COOKIE_SECURE=1`，否则口令和照片都是明文过网，这一步不是可选的装饰。

## 生成来源

「设置 · 换生成来源」（主页顶部那个链接，或直接访问 `settings` 页面）里二选一，存进 `data/settings.json`，
每个请求现读一次 —— 改完立刻生效，不用重启服务。**默认是不花钱的本地**：全新装、或者设置文件读不出时都走
ComfyUI；它没起来的话进首页就会当场告诉你并切到 API（下面那条规则，2026-11-01 起）。

**来源和档位一改就存盘**，不用找保存按钮（2026-11-01 起）。原来是文末一颗「保存」，而「回试衣间」在标题上头 ——
点完设置往上走的人根本看不见没保存这件事，真就这么白改过一盘。整页只剩 ComfyUI 地址要手动存：
它得连着自检一起看，一边敲一边存会把没敲完的半截写进盘里。那颗按钮、"存没存"、以及这一次生效的是什么都钉在
**屏幕下沿的常驻条**上，顶栏「← 试衣间」旁边再给一句三字的短结论。

- **token plan API**：`qwen-image-3.0-pro`，1K 一次 58 credit、2K 一次 108 credit；1K 实测 46–107 秒。
  2026-10-27 16:20 的额度读数：已用 12426 / 25500（48.7%），按 58 一次折算剩约 **225 次**，12 天后重置。
  **它按面积分档，最低就是 1K**：2026-10-31 实测请求 `size=496*616`（0.31M），入账正好 +58.000，
  而 `usage` 回的是 `output_width/height = 896×1152` —— 小尺寸它根本不执行，只把请求归进 1K 档。
  所以 480p 这一档在 API 那条走不到（`prefs.clamp_size` 会收成 1K），别指望用低档省额度。
- **本机 ComfyUI**：`qwen-image-2.1 turbo`，走 `http://<设置页里填的地址>`，不花额度。
  2026-10-31 同机连测（8 步采样，896×1152）：**95.1 / 95.4 / 96.2 / 98.4 秒**；1152×1536：180.3 秒（另两次是 205 / 224 秒）；
  2K 档（`resolution=2016`）：**539.62 秒**；720p 档（`resolution=864`）：**70.5 / 70.6 秒**；480p 档（`resolution=544`）：**26.0 / 26.1 / 26.2 秒**。
  耗时几乎正比于**这一档的总像素**，同尺寸之间还有 ±15% 上下的波动（取决于显存里还留着谁）。

两条路输出的宽高比都跟人相一致，档位共用同一个开关（默认 1K；面积上限 480p ≤307,200、720p ≤786,432、
1K ≤2,250,000、2K ≤4,157,440），提示词是同一份 `tryon/prompt.py`。只有两档低的例外：它们是本地专属，
来源切到 API 时会被收成 1K。
图库里每条记录带来源角标（`本地` / `API`），`meta.json` 里有 `source` 和 `band`（`480p` / `720p` / `1k` / `2k`）——
事后分得清是谁出的、出的多大。`size` 记的是**真正回来的那张**的尺寸，不是我们请求的那个数。

**ComfyUI 不在线：进首页那一刻当场说、当场切**（2026-11-01 定的规则，替掉了原先那句"只报错、绝不换 API"）。
首页加载会 POST 一次 `/api/comfy/fallback`，后端只打 ComfyUI 的 `/system_stats` 一个接口、只等 3 秒
（`comfy_api.healthy`；设置页那个自检是 4 个请求 × 10 秒，放首屏会把页面拖死）。探不到就把设置写成
`api` + **1K**，并弹一个对话框把原因、档位、一次多少 credit 说清楚，页眉那行同时变成真话
（实测：`还能试穿 168 次 · 1K 档一次 58 credit · 7 天后额度重置`，不再挂着"不花额度"）。

四条边界，都是为了让这件事不 surprises 人：

- **为什么在进页面时切、不在点"开始试穿"时切**：换来源就是换模型换价钱，藏在一次点击底下等于在质量线上挖坑。
  进页面切完，人看到的确认框、页眉、档位全是切完之后的状态。
- **来源本来就是 API 的人不去探**，一个请求都不发 —— 已经付过一次的决定不该每天被追问。
- **本机还有任务在跑时一律不判死**：`/api/comfy/fallback` 先看 `data/generating.lock`，有人拿着锁就直接回
  "不切"。正忙着出 2K 的 ComfyUI 恰恰最像"没应答"，那一刻判死就是替人花 58。
- **档位一律收成 1K**：自动切换不替人花 2K 那 108 credit，也不留着只有本地才有的 480p / 720p。
  想在 API 上跑大档，自己去设置页点。ComfyUI 的地址**原样留着**，切回来不用重填。

探活只回答"进程在不在"：权重没下、缺 `TextEncodeQwenImage21` 节点这些都算在线，那种错该在生成时原样报出来
（那是设置页「测一下能不能连上」管的）。**ComfyUI 起来之后不会自动切回来** —— 来源是 api 时那次探活根本不发，
得人去设置页点回「本机 ComfyUI」。

部署在别的机器上时，ComfyUI 地址要填那台机器能到的（比如 frp 映射后的端口），不是 `127.0.0.1`。
设置页的「测一下能不能连上」会分开告诉你是端口不通、缺 `TextEncodeQwenImage21` 节点、还是权重文件名对不上。

## 三个分类

首页顶上三个 tab：**一件衣服**（`single`）、**上衣加裤子/裙子**（`outfit`）、**换个发型**（`hair`）。
分类决定的是**除了人像还有几张参考图**，以及发出去的是哪条指令 —— 三张指令都在 `tryon/prompt.py`，
人像恒为「图像1」，参考图按槽序往后排（所以"图像N"的含义就是槽序，不能插队）。

| 分类 | 参考图 | 本地实测耗时（720p） | 输出 |
|---|---|---|---|
| 一件衣服 | 1 张 | **70.5 / 70.6 秒** | 2026-10 起的基线，一条指令没动过 |
| 上衣加裤子/裙子 | 2 张 | **95.2 / 96.2 秒** | 衬衫和裤子的腰头门襟都上了身，脸和姿势没动 |
| 换个发型 | 1 张 | **67.1 秒** | 换成参考图那个发型，眼镜、白 Polo、手势全保留 |

- **参考图最多两张**，因为接口那一条只吃 1–3 张输入图（人像占一张，这是官方文档写的），
  本机 ComfyUI 那个编码节点其实支持到 16 张 —— 是接口卡住了上限，不是没做。三件一起换走不到。
- **多一张参考图约多 1/3 时间**（95 ÷ 70 = 1.36）。这个倍数只有 720p 是量出来的，
  页面上别的档位按它推，句子里明说是推的（`MODE_FACTOR` 只乘本地那条，API 没依据）。
- **档位比例仍然由人像决定**：官方文档说"多图输入时输出比例以最后一张为准"，实测本地那条
  三张图进去还是出 768×992（人像的比例），那条说法在这台工作流上不成立。
- 第二格叫**裤子/裙子**、指令里写成「下装（裤子或裙子）」，因为女装那张参考图多半是裙子：
  光说裤子，裙子进去会被换成一条裤子。上面那两个耗时和那句质量结论都是**用裤子量的**，裙子还没实测。
- 槽位没齐**一次生成都不会发**：套装少传裤子会拿到 400 并且说清是哪个槽空着，
  一件衣服却塞了两张同样 400 —— 静默丢掉一张会让人以为裤子也换上了。
- 分类是**每次请求**带的字段，不写进设置：换分类不是换配置，`localStorage` 记一下只为下次打开还在原地。

## sample 图库

`data/samples/<大类>/<细分类>/<图>.jpg`，**目录结构本身就是图库**，没有清单文件要维护 ——
放一个文件进去，页面下次打开就有它。细分类可以不要（发型那两类就是直接躺在大类下面），
那一节用大类自己的名字。

**名字一律用英文**：字母、数字、点、短横线、下划线，中文目录名一律拒（管理页和接口都拒）。
理由是中文目录名在传文件、拼 URL、换终端这些场合会出事，而挑图那条路最后是要把文件名送给
ComfyUI 的。界面给人看的是中文，来自 `tryon/samples.py` 里那张 `LABELS` 表
（`menswear` → 男装、`top` → 上衣、`bottom` → 裤子/裙子），**表里没有的名字照原样显示**。
大类顺序写死成 **menswear / womenswear / hair-men / hair-women**，临时加的目录跟在后面。

- 首页每个格子右上角那颗「从图库选」打开弹层：挑一张 → 前端把原图取回来填进那一格，
  之后和本地上传的图**没有任何区别**（`/api/tryon` 的输入协议没为图库改过一个字）。
- 缩略图按 240 长边现算，缓存进 `data/samples/.thumbs/`；`.` 开头的一律不算分类，
  所以缓存不会变成一个能点的 tab。源图比缓存新就重算。
- 图库里的路径先验形状再看归属：`..`、绝对路径、点号开头的都拒，`resolve` 之后还要问一次
  是否仍在库内（库目录里塞一个指向外面的软链接，光比字符串拦不住）。
- 三个读图端点都以 `api_` 开头，所以登录网关照样拦 —— 图库里是人像和衣服照片，和记录同级敏感。
- **改图库不用上命令行**：`/samples-manage` 那一页能加图（多选）、删图、建空架子、改大类与细分类的名、
  把某张图挪到别的架子。弹层右下角有入口。三个约束是刻意的：
  - **撞名不覆盖**，编号成 `denim-shirt-2.jpg` —— 覆盖的话人会把上一张同名的好图丢掉；
  - **只有空架子能删**，里面还有图就报「top 里还有 3 张图，先清干净再删这一类」，
    一句"删掉这一类"不该连带抹掉几十张商品图；
  - 分类名带斜杠、以点号开头、用中文，一律拒；改名走的是同一个 `move`，所以**旧路径的缩略图缓存整棵删掉**
    （缓存按路径存，留着就是孤儿 —— 2026-11-01 浏览器实测漏清过一次）。
  空架子也会出现在树里（`items` 是空表），不然刚建好的那一节看不见，人会以为没建成再建一次。

## 输出尺寸：480p / 720p / 1K / 2K

设置页里四选一（**默认 1K**，`.env` 的 `TRYON_SIZE` 是它的默认值）：

| 档 | 输出总像素上限 | 本地实测耗时 | API 单价 | 浏览器上传长边 |
|---|---|---|---|---|
| 480p | 307,200（= 480×640） | **26 秒** | 走不到（见下） | 1536 |
| 720p | 786,432（= 768×1024） | **70 秒** | 走不到（见下） | 1536 |
| 1K | 2,250,000 | **95 秒起** | 58 credit | 1536 |
| 2K | 4,157,440（= 实测成立的 1792×2320） | **543 秒** | 108 credit，**不是 58 的两倍** | 2048 |

名字按 480p 那个思路排下去，但**上限写的是实际数**：这一档的 720p 是 768×1024，不是 1280×720
（后者 0.92M，同法实测 84 秒，多那 14 秒只多 15% 像素，不值）。

- **耗时几乎正比于这一档的总像素**，这是加低档的唯一理由：同样的图、同样的 8 步，
  把面积从 1.03M 降到 0.31M，本地一条从 95 秒变成 26 秒（3.6 倍）。480p 的用途是筛子 ——
  26 秒看清"这件衣服配这张脸行不行"；720p 是能直接发给人看的那一档：同一对图，768×1024 上
  牛仔布的织纹、口袋缝线、领尖和皮肤纹理都分得开，480×608 那一张这些全糊在一起。
- **1K 那一档真正花时间的是你手机的照片**：896×1152 的样片是 95 秒，1152×1536（1.77M）实测
  180 / 205 / 224 秒。两档低档把这根长尾砍掉 —— 720p 的 70 秒是对着 1K 的 180 秒比的，不是对着 95 秒。
- **480p 和 720p 只有本机 ComfyUI 有。** 接口按面积分档，最低就是 1K：实测请求 `496*616` 照样扣 58.000、
  而且它不出小图（回传 `896×1152`，就是参考图的尺寸）。所以来源是 API 时这两档会被 `clamp_size` 收成 1K，
  设置页里那两项也直接按住 —— 花一样的钱拿一样的图，没有"低档"这回事。
- **低档和 1K 是同一条规则：档位是上限，不是目标**（`comfy_resolution` 只在参考图超出
  307,200 / 786,432 / 2,250,000 时才压到 `resolution=544` / `864` / `1472`，本来就在预算内就 `0`、原样出）。
  本来比这一档小的图不去放大它 —— 放大花的时间和铺满一样，细节一点不多。只有 2K 把档位当**目标**（恒 `2016`），
  参考图小也铺满，否则"选了 2K 还是出 1K"没人看得出来是为什么。
- **输入多大不影响耗时**：实测输入 1.77M / 0.79M / 0.31M 配上 544 的预算，三次都是 26 秒。
  所以低档不降上传长边（降了只丢条件）；只有 2K 才需要更大的输入，因为那一档要的是更大的输出。
  放大不产生细节：896×1152 的人相出 2K，是把同一张脸铺大，不是多出纹理。
- 页眉的"还能试穿 N 次"按**所选档位**的单价折算，确认框里的 credit 数、失败文案里的扣额度数都跟着档位走。
- **2K 只有接口那条给选**（`prefs.API_ONLY_SIZES`）：本机 2K 实测 543 秒，而线上 `uwsgi.ini` 里
  `harakiri = 120` —— 跑到两分钟就被 worker 掐了，选了只拿到一个失败。存过 `comfyui + 2k` 的人
  读出来就是 1K，设置页那一档在来源是本机时按住并写明为什么。
- **2K 慢不是"显存不够往外挤"**：这台机器是 128GB 统一内存，实测把 8.9GB 文本编码器重新搬进显存那一次
  只比不搬的那次慢 3 秒（98.4 vs 95.4）。2K 就是 4.07M 像素 × 8 步，摊到每步 68 秒 —— 时间涨得比像素略快，
  但没有"往外挤"这回事。超时上限仍然给到 900 秒（实测值的 1.7 倍），那是**上限不是预期**；
  真不够时会原样报 `CUDA out of memory` 之类的错，不花钱，重来一次就行。
- API 那条的 2K 耗时**没有实测**，页面上那个估算基数（170000 毫秒）是按像素比推的；
  1K 的实测区间是 46–107 秒。要准数就得真跑一次，一次 108 credit。

两条边界说明白：**没设口令时服务无鉴权**，局域网内任何设备都能改来源和地址 —— 改成谁，你之后上传的照片就发给谁；
设了 `TRYON_PASSWORD` 之后这件事归登录管（见上一节）；
另外 `data/settings.json` 坏到读不出时回落到同一个默认（本地），所以不存在"静默被扣 58"那件事。

## 用法

1. 顶上先挑分类，再逐个格子选图：你的照片（正面、单人、光线均匀）、上衣 / 衣服（只放这一件）、套装还有第三格裤子/裙子
   （平铺挂拍都行，从头到尾拍全）。每格两条路：点格子本身从本地选，或点右上角「从图库选」从 `data/samples/` 里挑。选完先在浏览器里压到长边 1536
   （和服务端本来要缩到的尺寸一致，所以手机只传几十 KB 而不是几 MB，接口拿到的像素没变），
   取景框里画 720 宽的缩略图。处理期间格子里写「处理中…」，那时点不动开始按钮。换分类时藏起来的那一格会清空，
   不会留下"看不见但还在提交里"的图。
   浏览器不配合（没有 `createImageBitmap`）就退回原图上传，功能不受影响。
2. 点「开始试穿」先弹确认（走 API 时写明这次花多少 credit、本月还能试穿多少次；走本地时说"不花额度"），点确定才真的上传调接口；
   「再来一次」同样要确认，它一样花钱。
3. 卷尺先显示**真实**上传进度（`上传中 62% · 4.1/6.6 MB`），传完换成 `已上传，生成中 · N 秒`
   —— 生成那一段接口不给任何进度，只能按 90 秒估，旁边的秒数是真实计时。一张图约 80–100 秒
   （实测最快 46 秒，慢的时候 100 秒往上）。上传进度只覆盖「浏览器 → 本机」这一段；
   「本机 → 接口」那一段接口只回一个最终 JSON，没有流式通道，测不出百分比。
4. 不满意点「再来一次」，不用重新上传，换随机种子再出一张。**同一时间只允许一个任务在跑**：锁是
   `data/generating.lock`（不是进程内的 `threading.Lock` —— uWSGI 四个 worker 互相看不见那把锁，
   两个任务会同时压同一块显存）。有任务在跑时开始按钮按住，提示行写「上一次还在跑（本地 ComfyUI ·
   已 N 秒）」，这个秒数来自后端，不是前端自己猜的；硬要发请求会拿到 409。拿着锁的进程被杀掉时
   锁最多可信 30 分钟（`STALE_AFTER_S`，比 2K 的 900 秒上限宽一倍），超时就接管，不会把页面永久锁死。
5. 结果下面那行小字：走 API 时是接口回传的消耗数字（输出尺寸、档位、张数），走本地时写「本地 ComfyUI · 输出 … · 用时 …」。
6. 图库每页 5 条，底部按 1 2 3 翻页；点缩略图看大图，可以下载或删除整条记录。

图片方向（EXIF Orientation）现在由浏览器压缩那一步定死，不再靠服务端转 —— Chrome/Android 实测正确
（存的是横图加 `Orientation=6`，压完是 768×1536 的竖图）。代价是有损压了两次（浏览器 q0.92、服务端再 q0.92），
换来的是手机上行从几 MB 变成几十 KB，接口看到的像素尺寸和以前一致。

输出按设置页那一档来（480p / 720p / 1K / 2K，默认 1K）、一次 1 张、无水印；提示词写死在 `tryon/prompt.py`，
改动它等于改质量验收线（设计文档 6.6 节是基线）。

一次成功的 1K 生成实测扣 **58 credit**（2K 档 1792×2320 实测 108 credit，不是两倍关系）。
页眉那行"还能试穿多少次"是后端调本机的 `qianwen subscription status` 算出来的
（剩余 credit ÷ 58，向下取整），查询本身不计费；命令不在 PATH 上就只显示"额度查不到"，不影响生成。
**客户端超时不等于没花钱**：实测有一次 300 秒没回包、客户端报了 502，额度在 8 分钟后照样扣掉。

## 图存在哪

`data/records/<时间戳-随机码>/` 一条记录一个目录：

```
person.jpg   garment.jpg   garment2.jpg   result.png   thumb.jpg   meta.json
```

`garment2.jpg` 只有套装那次会有（列表按磁盘上真有什么来报，不靠 meta 里的分类）。
`meta.json` 里有时间、耗时、**分类**、**真发出去的那条指令**、输出尺寸、接口回传的 `usage` 和 `request_id`。
接口给的结果图链接 24 小时就失效，所以每次生成完立即下载落盘，之后离线也能看。

## 挂在 uWSGI 上跑

`mfr_wsgi.py` 是给 `/www/webroot/uwsgi/uwsgi.ini` 那个共享实例用的入口（`mount = /mfr=mfr_wsgi:app`，
另外四个站共一个进程组）。两件事只有在这种部署方式下才会碰到，都记在这儿：

- **路径不能靠当前工作目录**。实例的 `chdir` 是 `/www/webroot`，所以记录目录写死成
  `settings.PROJECT_ROOT / "data" / "records"`（`PROJECT_ROOT` 由 `__file__` 反推）。
  留 `"data/records"` 的话，部署实例会把上传的图写到站点根目录去。
- **超时链是 生成时限 900s < nginx 930s**。原来是 130s（只为盖住 `harakiri = 120` 配的），
  结果任何一次不算热的本地生成都会被 nginx 先掐：客户端看到失败，worker 继续跑完、图落进图库。
  2026-10-30 实测那一跑了 224.4 秒，日志里是 `generated 0 bytes ... Broken pipe`。
  改完拿本地 2K 撞了一遍：**543.77 秒，HTTP 200 正常回包**（`generated 1448 bytes in 543816 msecs`），
  页面上的「上一次还在跑」那条提示也就是为这种长任务准备的。
- `harakiri = 120` 是实例级的、五个站共用，按配置它应该先杀掉这些请求 —— **实测两次都没杀**
  （224.4 秒和 543.8 秒都活着跑完，`switches` 有值：轮询里的 `sleep` 大概在给看门狗复位）。
  我没敢把可靠性押在这上面，所以真需要长任务的时候是靠 nginx 那 930 秒撑着的；
  要收紧成"卡死 120 秒就杀 worker"，得先给这个站点单独一个 ini（像 `humanize.ini` 那样）。
- **设置文件的临时名每次不同**（`tempfile.mkstemp`，不是写死的 `settings.json.tmp`）：这个实例是
  **4 进程 × 2 线程**，同进程里两个请求就能撞在一起。2026-11-01 首页那次探活就是活案例 —— 一次页面加载
  发出两个 POST（`pageshow` 在首次加载也算一次），日志里是 `FileNotFoundError: settings.json.tmp` 配一个 500；
  比 500 更坏的是另一种走法：谁先 `replace` 谁就把对方写进去的内容当成自己的存了盘。
- **权限写死，不靠 umask**：那个实例的 `Umask` 是 `0000`，交给默认值就会落成 `data/` 777、
  记录目录 777、`settings.json` 666（里面是人脸原图，同机还跑着别的站）。现在建目录一律 `700`、
  建文件一律 `600`（`records.py`、`prefs.py`、`joblock.py`、`auth.py` 各自写死）。
  注意 `Path.mkdir(parents=True, mode=...)` **不会把 mode 传给顺带创建的父目录**，`save_record`
  里对 `records/` 单独 chmod 过一次，别照着"传了 mode 就完事了"改回去。

## 出错的时候

结果区显示接口原话，不改写。带上 `code` 和 `request_id` 去查最快：

- `Throttling` / 每分钟 5 次请求超限：等一会儿再点。
- 结果图下载失败：那次额度已经花掉了，页面会把原链接亮出来，24 小时内可以自己另存。
- `The read operation timed out`：600 秒还没回包。这次额度多半已经扣了，图却拿不回来，图库里也不会有这条。
- 页眉显示"额度查不到"：`qianwen` 命令没装或不在服务进程的 PATH 上，生成不受影响。
- 报错里出现「连不上 ComfyUI（http://…）」：地址填错、换了机器没改地址、上传或出图途中传输断了，
  或者 ComfyUI 是**在你打开页面之后**才挂的（首页那次探活只问那一下，问完就信了）。
  具体哪项由设置页的自检告诉你：端口不通、缺节点、还是权重名不对。
- 自检说「`UNETLoader` 的 `unet_name` 里没有 …」：那台 ComfyUI 没下这套权重，本地这条路用不了，切回 API。
- 本地生成报「`CUDA out of memory`」之类的原话：ComfyUI 显存不够，先关掉别的模型再试。
- 提示"连不上本机服务"：`dev_run.py` 没在跑。
- `409 上一次还在跑，请等它结束`：真有任务在跑（`data/generating.lock` 被人拿着），不是页面卡住。
  等它结束就好；**如果这一边的连接被 nginx 掐断过，图其实已经生成完并落进图库了**，刷新后去图库看，
  页面也会在锁放开的那一刻自己把图库刷出来。
- 提示行写着「上一次还在跑（已 N 秒）」可 ComfyUI 那边明明早结束了：拿着锁的进程被杀掉了（reload、
  harakiri、断电）。锁最多可信 30 分钟，到点自动接管；急着用就删掉 `data/generating.lock`。
- 页面把你送到 `/login`、或接口回 `401 还没登录`：cookie 到期（30 天）或口令换过，重登一次即可。
- `429 错太多次了，等 N 秒再试`：同一来源连错 5 次的冷却，时间到了自动放行。
- 部署后**一片空白**：多半是公网入口没口令拒绝启动。屏幕上会写原因（`mfr_wsgi.py` 里那条），照它加 `TRYON_PASSWORD` 再 reload。
- 每次开页面都要重输口令：`data/secret.key` 没写成（`data/` 不可写），或者被删过。

.venv/bin/python -m pytest -q

免得被路由的兜底分支吞成一个看起来正常的 502）—— 因为默认来源是本地，测试少注入一个替身就会真的
连上你自己开着的 ComfyUI，而这种情况曾经真的发生过、并且测试还是绿的。
